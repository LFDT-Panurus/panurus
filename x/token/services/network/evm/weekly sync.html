06 / 08
Endorsement flow
The translator and signer wired into an actual flow over FSC sessions.
Responder
authorize the caller, validate against on-chain state, translate, sign
recomputes the digest itself and never signs one handed to it
so a bad initiator cannot get it to sign something it did not validate
Initiator
collects signatures and assembles the quorum
recovers each signature to a distinct registered endorser first
the same rule the contract enforces, so it never builds a quorum that would be rejected
week 4 gate — passed
a 2-of-3 quorum assembled over in-memory sessions verifies on the real contract.
plus the address to identity registry and a dependency-free ABI codec · PR #1988 merged

The driver comes alive
Everything built so far now runs as one system against a real node.
Talking to a node
JSON-RPC client over plain eth_* methods, works on any standard node
RLP encoder and EIP-1559 transaction signing, hand-rolled
ABI write codec for applyStateDelta, the nested dynamic tuple
config, version keeper, nonce manager, submitter
The driver surface
all the network methods: approval, broadcast, queries, finality
ComputeTxID mutates the id, as FSC and the fabric driver do
finality resolves from the chain alone, so a restart needs no stored state
by anchor only success is observable, a revert leaves nothing behind
week 5 gate — passed
against a real node: deploy, issue, transfer, double spend refused, finality read back, all through the driver's own path.
two golden vectors verified with cast, not just against our own code · PRs #2082 + #2094 merged
