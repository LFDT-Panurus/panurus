# Proposals

This folder holds proposals that change how the project works: process, policy, or cross-cutting design.

## Lifecycle

1. **Draft.** The author opens a PR that adds `docs/proposals/<topic>.md`. Maintainers discuss it in the PR.
2. **Iterate.** The author updates the proposal in the same PR until maintainers agree.
3. **Accepted.** The agreed content moves into the official documentation, for example `docs/development/`. The proposal file is then removed, or kept with status **Accepted** and a link to the official page.
4. **Rejected or withdrawn.** The PR is closed. The reason stays in the PR discussion.

Each proposal starts with a header table: **Status**, **Author**, **Date**, and **Base commit** when relevant.
