# Vulnerabilities that `make govulncheck` (ci/scripts/govulncheck.sh) is
# allowed to report as reachable without failing the build.
#
# Add an entry ONLY when the OSV report has no fix available (Fixed in: N/A)
# or a fix cannot be adopted yet, AND the reachable call path has been
# reviewed and judged not exploitable in Panurus's usage. Include the OSV ID,
# the module it comes from, and why it's safe to ignore here. Re-review (and
# ideally drop) each entry whenever the pulling-in dependency is upgraded.
#
# UNREACHABLE findings need no entry here, and must not be given one: this
# file is consulted only after govulncheck exits non-zero, which a
# module-level-only finding never does, so an entry buys nothing today and
# suppresses the failure CI should raise if the finding ever does become
# reachable.
#
# GO-2026-5932 (golang.org/x/crypto/openpgp) is the standing example, and is
# deliberately absent. The package is unmaintained with no fixed version
# (introduced: 0), so no x/crypto bump clears it — but it is in the import
# graph of no module, test binaries included, so it is never linked into a
# Panurus binary, and govulncheck reports it only under "Module Results",
# 0 called. Re-check in any module with:
#     go list -deps -test ./... | grep golang.org/x/crypto/openpgp
# If that ever prints a package, port the call site to a maintained fork
# rather than adding an entry here. Full evidence: PR #2464.

GO-2024-3218

# GO-2026-6443: DoS via server panic on requests lacking both :authority and
# Host headers, in google.golang.org/grpc. The panic is raised only inside
# grpc's xDS routing interceptor (internal/xds/server.RouteAndProcess) and is
# triggerable only when the server is configured with xDS routing. Panurus's
# only reachable grpc server on this path is the token chaincode-as-a-service
# server (shim.ChaincodeServer in token/services/network/fabric/tcc/main/main.go),
# a plain chaincode gRPC server with no xDS routing that accepts connections
# only from the Fabric peer over mTLS inside a permissioned network -- so the
# vulnerable xDS code path is never configured or exposed. govulncheck reports
# it via http2Server.HandleStreams (called by every grpc server), not the xDS
# sink. The only fix at/above the grpc v1.84.0 that fabric-smart-client requires
# is an unreleased v1.85.0-dev pseudo-version; the stable v1.83.2 fix predates
# that pin and cannot be adopted. Re-review when FSC's grpc dependency moves to
# v1.85.0+.
GO-2026-6443
